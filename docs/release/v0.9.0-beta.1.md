# P2B Order 12 — MyPet v0.9.0-beta.1 internal beta

## Scope

The first beta is a controlled Tirupati internal distribution for customer and operational applications. It is not a public Play Store or App Store release.

## Build identities

- Customer Android: `com.mypet.customer`, version `0.9.0-beta.1`, versionCode `901`
- Customer iOS: `com.mypet.customer`, version `0.9.0-beta.1`, build `1`
- Operations Android: `com.pawsnearme.merchantcaptainapp`, version `0.9.0-beta.1`, versionCode `901`
- Operations iOS: `com.pawsnearme.merchantcaptainapp`, version `0.9.0-beta.1`, build `1`

Both EAS `internal-beta` profiles disable demo mode and use internal distribution.

## Fail-closed authorization

Merging Order 12 installs versioned build configuration and the release workflow. It does not authorize a tag or distribution.

`release/v0.9.0-beta.1.json` must remain with:

- `tagAuthorized: false`
- `distributionAuthorized: false`
- explicit blockers
- `NOT_BUILT` artifacts

until all evidence has been reviewed.

The release gate requires:

1. Java and mobile CI green on the release commit
2. Full Stack Smoke and exact ten connected journeys green
3. Every physical-device matrix check marked `PASS` with evidence
4. Demo mode disabled in both build profiles
5. Customer and operations Android/iOS artifacts built and linked
6. Database backup and restore evidence
7. Privacy policy, terms and pilot consent sign-off
8. Administrator audit-log verification
9. Staging payment, push and deep-link verification

## Validation

Configuration-only validation, expected to pass before device evidence:

```bash
python scripts/validate-internal-beta.py
```

Release authorization, expected to fail until the manifest and physical evidence are complete:

```bash
python scripts/validate-internal-beta.py --release
```

## Build commands after authorization

```bash
cd apps/customer-app
eas build --profile internal-beta --platform android

eas build --profile internal-beta --platform ios

cd ../merchant-captain-app
eas build --profile internal-beta --platform android
eas build --profile internal-beta --platform ios
```

Record every resulting artifact URL in the release manifest. Do not place signing credentials, EAS tokens or store secrets in the repository.

## Tagging

Create `v0.9.0-beta.1` only after `python scripts/validate-internal-beta.py --release` passes on the exact commit being tagged. A failed release gate is a release blocker, not an instruction to weaken the validator.
